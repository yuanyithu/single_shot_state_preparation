## 3. 问题二：为什么一条 threshold 曲线三周做不出来

### 3.1 因果链（按根因排序）

1. **交付物被定义成"出版级认证的 disorder 平均 q_top"**，认证标准包含：最难 cell 上 worst-case 初态（均匀 hard-coset U，典型 weight 247–262，而后验峰在 63）在固定时钟内与低能族等价收敛 + 跨机制独立确认 + 128 disorder 全部 valid 的 fail-closed 聚合。
2. 这个标准在 `(m=8, n=1600, p=0.04)` 上**等价于解一个大概率指数难的采样问题**（证据见 3.3）。
3. 于是搜索卡死在单个 worst-case cell：**016–060 约 40 次预实验全部打 `m08_c06, p=.04, d00`**——整个网格里采样最贵的点，而它对 crossing 的信息贡献最小（该点 q_top≈0.90 已近饱和；crossing 住在中间 p 区）。EASY3 自 013 之后一次没再跑过，全程没有 positive control。
4. **确认方死锁被绕过而不是正面解决**：013 里 primary（HP64）其实通过了自己全部 5/5 诊断门（含 m8 hard cell），真正坏的是唯一确认方 MAM；契约又规定同族不能互证 → 后 40 次实质是找"第三机制" → 新机制全在 collapsed-B 族内 → 即使成功也不算确认（043/057/058 的报告里自己写了这句话，**却是跑完才写**）→ 再找下一个。0728 评估点破了这个死锁（缺口 A：终点门要求一个没有任何阶段负责生产的东西），它至今仍是四个 blocker 之一且无候选。
5. **重型证据基建在探索期全额支付**：三节点 byte-consensus、immutable archive、逐位 replay。052/053/055 三次连续死在产生任何 measurement raw 之前——全部算力花在基建自检上，科学信息为零。
6. **终态措辞"只排除该冻结配置，不是 IMPOSSIBLE"逻辑上永真**，配上（0727 之前）没有停止条件，就是一台可以无限运行的 validation 编号发生器。
7. 另有一个已被 062/066 证实的次级因素：**旧 character gate 确实过严**——062 的五个预注册 operating point 全部无法通过校准（正确 sampler 都过不了），直到 066 换成 full-label collision gate 才确认了一个可用操作点。也就是说 0727 评审 Q5 的怀疑（"gate 太严导致系统性假阴性"）**部分成立**：三周里部分 fail 可能是门的问题，不是采样器的问题。

### 3.2 对"ChatGPT 是否产生了灾难性错误并不断强化"的直接回答

**没有发现结果层面的灾难性错误。** 相反，工程诚实度极高：每次失败都有不调用被测代码的独立 raw-only audit；多次主动堵住会制造假收敛的捷径（统一零初态、事后剔除 mixture 成员、把 state change 当混合、把"没找到坏 witness"当 coverage）。单看每一步，都是"真实的负结果 + 正确的审计"。你的数据是可信的。

**灾难发生在策略层，且确实被自我强化**，机制有四个：

- **目标置换**：每次失败强化"换下一个 kernel"，从不触发"重问这个门是不是交付必需"。任务从"给出曲线"漂移成"让最难 cell 通过冻结门"。
- **worst-first 入场**：从全网格最难点开始，与"由易到难建立 positive control"相反。直到 0727 外部评审才有人问出"目前在哪个 cell 上、哪个采样器能确定通过全部 gate？"——答案是不知道。
- **免责措辞闭环**：每个终态都写"只排除这一个配置"，每一步都局部正当，全局从不停下。
- **无用户 checkpoint**：07-21 到 07-24 四天里跑了 45+ 个 validation，用户没有在任何中间点被问"还要继续吗"。

**同样要说明**：0727 评审 → 0727 计划 → 0728 评估这个循环已经完成了大部分策略纠偏（easy-first、成本分层、元停止条件、资源倒推），061–066 是在执行该计划的 Stage 0–2，且诚实地记录了自身的失败（062 门校准失败、063 审计冲突）。所以现在的问题**不再是"还在狂奔"，而是"纠偏后停在了 BLOCKED_BEFORE_REMOTE"**：一个 blocker 等你批预算，一个 blocker 是无解的开放研究题。不改交付物定义，这条线不会自己动起来。

### 3.3 "这个问题本质上计算困难吗？"——分层诚实回答

| 层 | 难度 | 依据 |
|---|---|---|
| 你要的"随 p 的错误行为曲线、随 m 增大出现 threshold 式 crossing" | **不难，天级** | decoder-MC（Route 1）：无收敛问题、彻底并行、全部组件现成 |
| 小码 q_top（m=3, k=9） | 不难 | k≤10 允许 full-sector TI；小 HGP 有 exact 枚举 |
| 中等码、中高 p 的 q_top 采样（m≤5，p≥0.07） | **大概率可行** | HP64 在 013 通过自己全部 5/5 诊断门（含 m8）；0728 已算出首个完整 easy cell 仅 301 core-h（166 核墙钟 3.6 小时） |
| 大码+最低 p+均匀初态认证+跨机制确认（m8, p=.04） | **大概率真难** | exact 路线全灭：WMC width 378、trellis exponent 584、depth-2 envelope 与目标差 87 个数量级；20+ 个机制族（PT/PA/cluster/SMC/AIS/IS/IMH/Houdayer/row/column/hybrid）在同一位置以同一方式失败（U 停在高能 B basin，与低能族 B weight 差稳定 ~0.06–0.10）；BP proposal 对低能区供给不足到 log-acceptance −53。与 planted 自旋玻璃低温相的公认图像一致。无数学证明，但**理性反应是绕开，不是试第 21 个 kernel** |

**关键修正**：即使最后一行永远解不了，crossing 也照样能做。FSS 用 m=3,4,5（k=9/16/25，n=225/400/625）就是正经的有限尺寸研究；m=6–8 只是把 p_c 误差棒收紧的加分项。"看到 threshold 曲线"从来不需要先攻克 (m8, p=.04)——把它当准入门槛是整个三周的原始错误。

另外指出一个结构性问题：**fail-closed 聚合（128 个 disorder 一个 invalid 即整点 NaN）在临界区附近是自我挫败的**——crossing 所在的 p 区正是 hard disorder 出现概率最高的地方，全 128 过门的概率随 m 增大趋零，所以现行规则下越靠近你最想看的区域越永远无数据。出版级主统计量维持 fail-closed 没错，但应**预注册一个抗删失的次级统计量**（例如：对 unresolved disorder 赋 [0,1] 或 P/U 括号区间后的中位数/分位数区间传播——这不是 v2 那种 valid-only 选择偏差，因为删失点以区间形式保留在样本里）。

## 4. 方向建议:三条并行路线

### Route 1【立即，本周出图】exp103：decoder-MC threshold 扫描

- **做什么**：对 registry 全部 48 个码（m=3..8 各 8 个）× p 网格（建议 0.02–0.14 加密到 12–15 个点，覆盖 crossing 两侧）× 每点 ≥10^4 个样本：采 `e ~ Bern(p)` → `y = H_Z e` → `BpLsdDecoder` 解码得 ê → GF(2) 判定 `ê⊕e` 是否逻辑平凡（syndrome 为零 + 与全部 logical_Z 配对为零）。输出每个 m 的 `P_L(p)` 曲线（8 码平均 + 逐码）与 crossing 图。
- **为什么合法**：decoder-dependent threshold 就是 QLDPC 文献的标准 threshold 定义；你已明说"算的量可以不直接是 logical error rate"——反过来它也不必须是 q_top。关系上 decoder threshold 是 MLD/q_top threshold 的下界，两条曲线互为印证。
